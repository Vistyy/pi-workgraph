# Pi Workgraph implementation

## Outcome

Pi Workgraph provides durable outcome-driven orchestration for answers, decisions, product changes, and operations.
Every run records an explicit outcome statement and completion predicate.

## Runtime boundary

A run may declare optional named milestones with concrete descriptions.
Milestones are durable progress records and are never selected-skill lifecycle owners.
Non-change outcomes finish through typed evidence and a coordinator conclusion without implementation claims.
Product-change outcomes retain agreement, isolated bounded implementation nodes, deterministic exact-commit composition, exact-revision verification, assurance, and final coordinator judgment.

## Child boundary

Children use ordinary Pi configuration and resource discovery, retaining the configured tools, extensions, skills, and prompt templates.
The Workgraph package is role-aware: coordinator tools load in coordinator sessions, while assignment sessions load reporting support without removing unrelated resources.
Child session identity, terminal result, usage, and model provenance are durable for recovery and diagnosis.
Git worktrees isolate product effects, and authoritative Git postconditions validate implementation commits before composition.

## Guidance

The sixteen former procedures are optional Workgraph-owned Pi skills.
They provide composable guidance and do not own runtime state or lifecycle transitions.
Workgraph also owns verification strategy, browser and UI control, CLI and TUI control, project verification-skill creation, project verification-skill maintenance, and evidence doctrine.

## Evidence and assurance

Discovery and assurance distinguish direct evidence, inference, conflicts, and unknowns.
Blast-radius-sensitive changes must prove the relevant external safety fact at the actual dependent boundary.
Product verification prefers repository-native harnesses, then a project-local verification skill, then the appropriate Workgraph control skill.
Unavailable required control surfaces produce inconclusive verification.
Creation and maintenance of project verification skills remain repository-changing coordinator capabilities.

## Verification

The retained gates are `pnpm check`, `pnpm pack --dry-run`, `pnpm smoke:real`, and `pnpm smoke:coordinator`.
Deterministic coverage protects outcome contracts, milestone persistence, child accounting, ordinary resource loading, exact composition, recovery, evidence routing, assurance, and final judgment.
Model-backed smokes exercise both direct engine and coordinator package boundaries when credentials are available.
